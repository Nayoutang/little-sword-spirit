# 第二阶段：逐段结算记录

本次只改敌方结算，不加入回锋、留盾和护盾攻击。小墨正式出招仍由 LLM 决定；回归重放保存的意向与牌序，不重新生成意向或规划动作。

## 已实现规则

敌人从左到右，攻击按展示的段顺序执行。每段先减伤、扣盾、扣血，再处理保命和玩家死亡；玩家存活才进入反击入口。零伤害、完全格挡仍进入入口；拦截或取消的段不进入。反击击杀攻击者后取消其剩余动作，玩家死亡则停止敌方阶段。

霜寒每段减2；拨千斤只影响指定敌人的下一段；阴山比较修正后的总攻击伤害，拦截最高敌人的全部攻击段，同值取最左侧。小墨格挡与玩家格挡共用护盾池，未来计入留盾；目前记录两类新增来源、敌方入伤、实际耗盾与回合末作废护盾。

回锋尚未实现，R/C 独立上限的真实卡牌验证留到下一步。测试中的反击监听器只验证结算入口和反杀取消逻辑。

## 验证结果

逐段边界检查及主动连击检查均通过。覆盖多段扣盾、零伤害、霜寒、拨千斤、阴山、反杀取消、致命段不反击和保命后反击。

保存的 v2 120 场分别由旧合计结算与新逐段结算重放：3185 个决策状态、随机数轨迹及消耗计数匹配，120 个最终随机状态匹配；胜负、生命、出牌、抽牌、小墨意向及原有逐回合指标与原档一致。比较前将日志数字归一化，避免 0 与 0.0 的表示差异误报。该一致性只适用于这批没有受影响特殊效果的配置，不用于证明霜寒等新语义与旧结果相同。

复核工具：`tools/enemy_segments_smoke.gd`、`tools/verify_enemy_action_regression.ps1`。后者读取原档及 `.godot/combo-action-regression-{sequential,legacy}.jsonl`。

## 防御压力基线

统计 531 个实际完成的敌方阶段，不包含玩家提前结束战斗后的未执行阶段。

|阶段|次数|玩家新增盾|小墨新增盾|敌方入伤|实际耗盾|作废盾|
|---|---:|---:|---:|---:|---:|---:|
|有执行攻击段|505|505|3018|5866|3361|162|
|无执行攻击段|26|20|42|0|0|62|

有攻击阶段合并耗盾率 95.4%，作废率 4.6%；全部阶段耗盾率 93.8%。小墨占新增护盾约85.4%。生命压力较低与护盾留存空间较小可以同时发生，不能用剩余生命代替护盾曲线。

撤回30%–50%耗盾率目标，也不将原1.0–1.3比例套用于间歇场景。下一步分别报告重击入伤/重击回合新增盾及重击入伤/完整周期新增盾：先保证无留盾基线会受伤但能完成战斗，再观察周期比值；0.65–0.8只作候选观察区间。平均比值不能单独判断无限累积：无留盾时空档护盾作废，有留盾时可跨回合；反击击杀、护盾攻击提早结束战斗又会改变实际入伤。按周期相同相位记录护盾余额及重复撞击伤害，区分有限战斗积累与持续正增长。

方案与资源表见 [护盾构筑标定草案](shield-build-calibration-2026-10-06.md)。当前离线规划器尚未针对多段新语义升级，先用固定脚本策略，不升级规划器。
