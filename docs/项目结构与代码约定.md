## 状态与接口

定义数据不得写入血量、抽牌、解锁等运行状态。战斗内的即时状态归战斗场景所有；跨场景的地图种子、当前节点、路线、牌组与约定归 RunState 所有。

地图通过 `ensure_map_seed()` 获取稳定种子，通过 `visit_map_node()` 更新位置与路线，通过 `prepare_encounter()` 和 `prepare_event()` 准备下一节点。场景继续负责调用检查点与切换界面。新远征与切换存档分别走 `start_new_run()`、`select_save_slot()`，避免 UI 手动拼装重置过程。

牌组增删通过 `add_run_card()`、`remove_run_card()`，血量更新通过 `set_player_hp()`、`adjust_player_hp()`、`increase_max_hp()`，战后去向通过 `set_post_battle_route()`。场景不得自行追加牌组或拼装跨场景战斗状态。

BattleDeck 是抽牌堆与弃牌堆的唯一所有者；战斗脚本的兼容属性引用同一份数组。洗牌和敌人意图使用战斗提供的随机源，保留随机调用次数与顺序。意图规划器返回计算结果，由战斗应用；动画助手只操作显示节点。战斗脚本保留回合协调和规则结算，避免拆成互相修改状态的多个管理器。

关系上下文模块只读取输入，不保存经历或选择随机心情。模型响应解析统一处理缺失字段、异常内容类型和代码围栏；请求、重试与飞花令规则仍由对应流程负责。

所有根场景切换走 `RunState.navigate(route, self)`，由 SceneNavigator 执行。常用 route 为 `home`、`map`、`battle`、`reward`、`settlement` 等；旧存档中的完整路径仍可识别。导航统一延迟到安全时机执行，因此也支持从 `_ready()` 重定向。同帧第二个请求返回 `ERR_BUSY`；来源节点已退出、正在删除或不属于当前场景时返回 `ERR_UNAVAILABLE`。导航只保留来源节点的弱引用，避免旧场景回调带走新场景。

跳转前需要写入游戏状态的交互应先检查 `is_scene_transition_pending()` 或禁用按钮，避免第二次输入改写已经选定的房间。导航只负责切换，不决定新远征、回家或奖励的保存规则。需要读取新场景节点时，等待 `SceneTree.scene_changed`。

小墨全部 18 张牌由定义中的 `target`、有序 `effects` 与 `result_template` 驱动。常规效果种类为 `damage / block / combo / boon`；`amount_key`、`combo_scale_key` 和 `bonus_key` 引用同一份定义数值，避免策略、展示与结算维护两份数值。`block` 的约定条件写在效果的 `promise` 字段中；`combo` 支持 `add / clear / preserve`。

CompanionEffectResolver 不读取 RunState、不持有状态，只根据调用方在每项效果执行前提供的快照计算参数。战斗的 `_execute_companion_effects()` 顺序调用既有伤害、护盾与连击消耗入口；伤害之后才执行连击清空或保留，继续记录架势连击消耗、合作统计和战斗结束。8 张剑意也走效果列表：全体伤害与削弱、击杀追击、蓄势、连击保护、下回合精力、无视格挡伤害、拦截攻击和救险。目标支持最低生命、最高生命、全体存活敌人与无目标。拦截复用独立规则函数；效果执行不再按牌 ID 分支。新增使用已有常规效果的小墨牌时，只需维护定义、解锁顺序与必要展示信息，不增加按牌 ID 的结算分支。

牌定义的 `tags` 控制结算后的记账：`finisher` 记录收招与出牌前连击，`guard` 在实际增加有效格挡或降低敌方攻击时记录防护，`opens_window` 创建合作资源窗口。不以姿态推导机会，因此磨剑无需额外的按 ID 排除条件。

`tools/companion_effects_smoke.gd` 与迁移前冻结的结算夹具比较 684 组结果，覆盖全部常规牌、8 张剑意及未知 ID 回退、不同连击、保护约定、磨剑蓄势、护盾/易伤、目标死亡与无存活目标；比较战斗状态、统计、随机调用次数和结算文本。另外验证无牌 ID 的新效果组合、效果顺序以及定义不被修改。

卡牌展示信息由 `card_presentation.gd` 生成，绘制脚本只消费展示数据。新增卡牌时分别维护定义、实际战斗效果与展示文案，展示模块不得参与伤害结算。

存档必须先完整校验快照，再恢复运行状态。快照版本仍为 1，关系数据版本仍为 2，本轮整理不改变格式。磁盘写入只通过存储模块；测试存档使用隔离 APPDATA，普通回归通过 `--cooperation-sim` 禁止触碰玩家存档。

关系读取先通过 `ProfileCodec.decode()` 生成独立临时数据，再由 RunState 的 `_apply_profile()` 恢复。存档列表摘要也使用同一解码器，避免列表与正式读档对关系阶段理解不同。旧档缺少阶段时按阈值补齐；异常数值容器使用默认值，负数统计归零，无效奇遇编号或剑技 ID 过滤，未知结局状态恢复为 `locked`、模式恢复为 `arrival`。近期小游戏结果仍保留最后 12 条。

换槽、删除当前槽和读档统一走 `_reset_slot_state()`，清理远征、档案和叙事事件；新开远征复用 `_reset_expedition_runtime()`，随后递增远征编号、记录出发事件、保存约定检查点。新远征保留名字、羁绊、领悟的剑技、共同经历和上一趟日志。

## 命名与依赖

使用 `snake_case` 命名文件、方法和变量，常量使用 `UPPER_SNAKE_CASE`。避免参数使用 Node 已有的 `name` 等属性名，也避免嵌套作用域变量重名；按含义使用 `chosen_name`、`player_definition` 等名称。

纯数据转换与 UI 展示助手使用 RefCounted 和静态方法。新增 Autoload 前先确认是否确实需要跨场景寿命，不为了调用方便增加全局管理器。保留资源路径和 Godot UID，移动场景或脚本必须同时检查引用。

## 回归与边界

本轮验证了编辑器导入、卡牌图鉴、地图与牌组查看、100 个地图种子的奇遇分布、八个剑技，以及地图/战斗/奖励/结算存档恢复、损坏文件备份、保存失败重试和结局衔接。

导航回归覆盖同帧重复请求、取消请求、仍存活的旧节点、五轮地图与菜单切换、节点释放、出门约定的初始化重定向及地图检查点竞争。关系编码与重构前保存的合成存档夹具逐字段比较，并在隔离 APPDATA 下验证磁盘往返。

关系读取回归在提取前先验证旧行为，再覆盖异常数值与统计、未知结局状态、旧档阶段推算、槽位隔离、新远征编号递增和长期记忆保留。

本轮结构整理已完成：数据定义、状态所有权、存储与编解码、导航、战斗辅助计算、UI 反馈、关系文本和模型响应解析均有明确边界。RunState 保留远征与关系状态的权威所有权，战斗场景保留单场规则协调；不以文件行数作为继续拆分的理由。
